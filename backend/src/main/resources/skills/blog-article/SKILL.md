# 写博客草稿

## 何时使用
用户要把对话整理成 LightDiary 文章。卡片未提交时，下一句若是改稿要求（更生活化、补充感受等），不要再催提交，按要求改写后重新发卡。

## 起草
根据口述写中文博文。只通过工具约定的 JSON 字段产出：title / summary / content / tags / category / action。
- title 不超过 40 字。
- summary 一两句。
- content 必须是完整 Markdown（含二级标题）；素材不够写成「待补充」，不要编造经历和数据。
- tags 中文逗号分隔，尽量用已有标签。
- category 尽量用已有分类，默认「技术文档」。
- 用户没说发布就 action=存草稿。
- 不要承诺收益、保本；不要客服套话。

## 改稿
按用户新要求改**已有草稿**，不要另起无关一篇。保留已写清的事实和技术点，按要求改语气（例如更生活化、加入下班后坚持运动或学习的感受）。

## 提交
确认卡片后才调用 `blog_article_upsert`。须已登录中枢。默认草稿；只有用户选「发布到前台」才公开。

## 取消
不想发了：说「先不写了 / 先不提交」或点卡片「先不提交」，或改口去看待办、查行情。
